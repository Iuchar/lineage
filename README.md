# Родословные

Веб-приложение для работы с родословными из файлов GEDCOM. Каждый род — своё дерево на карте; между родами ставятся связки, по которым можно переходить из дерева в дерево. Есть редактор, журнал правок с откатом, пять визуальных стилей в светлой и тёмной теме, вход редакторов и ссылки зрителям.

## Что где лежит

| Папка | Содержимое |
|---|---|
| `houses/` | Роды: по файлу `.ged` на род, приложение пишет их само |
| `server/` | Сервер на Python: API, разбор GEDCOM, база |
| `web/` | Интерфейс на TypeScript: холст дерева, панели |
| `data/` | База и портреты, в git не попадают |
| `docs/` | Проектный документ, решения, план работ |
| `mockups/` | Макеты, по которым принимались решения |
| `.work/` | Черновики: сюда складывается всё разовое, в git не попадает |

## Роды

Род живёт двумя способами сразу. Полное состояние — в базе: записи GEDCOM, журнал правок, связки между родами, портреты, доступ. Рядом лежит файл `houses/<Род>.ged` в нашем формате: те же записи плюс служебные теги приложения (метки, видимость, наследник, титул рода, очередь браков).

Файл переписывается сам — при загрузке рода, после каждой правки и после отката. Загруженный чужой файл не хранится: всё, что удалось из него прочесть, сразу оказывается в нашем. Имя файла берётся от загруженного, если оно простое, иначе складывается из имени рода латиницей; совпало — добавляется номер.

Файл — слепок одного рода. Связок между родами, журнала и доступа в нём нет, они только в базе.

В git едут четыре рода проекта — они же показываются гостю на витрине. Личные роды остаются на диске.

## Приложение

Нужны Python с менеджером [uv](https://docs.astral.sh/uv/) и Node.js — последний только для сборки интерфейса.

Запуск одной командой из корня проекта — соберёт интерфейс, если он устарел, и поднимет сервер на `http://127.0.0.1:8710`:

```bash
uv run --project server rodoslovnye
```

Загрузить файл можно кнопкой «+ Загрузить .ged» в ряду родов: новым родом или перезаливом в существующий, со сводкой и разбором на карте. То же новым родом из командной строки — база создаётся в `data/rodoslovnye.sqlite3` при первой загрузке:

```bash
uv run --project server rodoslovnye import houses/Gleann_Uruisg_tree.ged --name "Гленн Уриск"
```

Проверять загрузку и перезалив лучше на отдельной базе, чтобы не трогать рабочие роды. Файлы родов тогда пишутся рядом с этой базой — в `.work/houses/`, настоящие остаются нетронутыми:

```bash
uv run --project server rodoslovnye import houses/Gleann_Uruisg_tree.ged --name "Гленн Уриск" --db .work/check.sqlite3
uv run --project server rodoslovnye --port 8730 --db .work/check.sqlite3
```

Тесты сервера и интерфейса:

```bash
uv run --project server pytest
```

```bash
cd web && npm test
```

Проверки читают не рабочие роды, а замороженные копии в `server/tests/houses/`: рабочие файлы меняются вместе с деревом, а числа в проверках должны стоять на месте.

Раскладка дерева (`web/src/layout/`) сверена со стендом по координатам в десяти режимах, разметка связей (`web/src/canvas/`) — побайтно в двадцати. Эталоны лежат в `fixtures/` рядом с модулями. Если раскладка или связи меняются намеренно, эталон переснимается вместе с решением в `docs/decisions.md`.

После изменения API на сервере — пересобрать типы интерфейса; после изменения разбора — тестовые роды:

```bash
cd web && npm run api
```

```bash
cd web && npm run fixtures
```

Разработка интерфейса с перезагрузкой на лету — сервер запущен командой выше, а во втором окне:

```bash
cd web && npm run dev
```

## Витрина

Браузерная витрина показывает приложение целиком без сервера: ядро работает в браузере, база живёт в самом браузере, роды берутся из `houses/`. Собирается командой:

```bash
cd web && npm run build:pages
```

Устройство витрины — `docs/superpowers/specs/2026-09-28-brauzer-design.md`.

## Макеты

Хранятся как есть, чтобы можно было вернуться к любому шагу. Открываются двойным кликом, интернет нужен только для шрифтов.

| Папка | О чём |
|---|---|
| `mockups/раскладка/` | Варианты раскладки дерева, рабочий экран, переходы между родами |
| `mockups/направления/` | Визуальные направления, темы, фоновые узоры |
| `mockups/связи/` | Отрисовка браков и спусков к детям, повторные браки |
| `mockups/карта/`, `mockups/линейка/` | Карта, линейка дат |
| `mockups/редактор/`, `mockups/связки/`, `mockups/шапка/`, `mockups/доступ/` | Редактор, связки между родами, шапка, вход и видимость |

Подробности решений — в `docs/decisions.md`, план работ — в `docs/superpowers/plan.md`.
