## Дизайн: что осталось

Пять направлений остаются все: это переключаемые стили приложения, а не конкурс с одним победителем. Значит каждая новая деталь делается для всех пяти.

- [x] Один известный родитель: связь выходит сбоку витым завитком, перенесено во все пять стилей.
- [x] **Светлые темы** «Гобелена» и «Ночного кабинета» нарисованы заново: «золотное шитьё» и «зелёная лампа».
- [x] Линейка дат: двойная шкала, ярусы по медиане со сдвигом к своему году, проверено на всех пяти стилях и обоих родах.
- [x] **Линейка дат в светлых темах** — проверена во всех пяти стилях на рабочем приложении: шкала, подписи поколений и выделенный ярус читаются.
- [x] **Метки и портреты.** Портрет-миниатюра и знак метки нарисованы для всех пяти стилей, есть выключатель портретов и фильтр по метке. Хранить метки и снимки пока негде, поэтому видно по адресу с `?demo=marks`.
- [x] **Люди без года.** Порядок среди братьев — по записи семьи, высота на линейке — по оценке по родне. В исходных файлах без года только заглушки, правило проверено снятием годов у настоящих людей.
- [ ] **Главенство линии.** Отдельное поле, которое задаёт человек. Ни возраст, ни размер ветки его не определяют. Решить, на что оно влияет: на порядок, на выделение или на раскладку.

## Данные

- [x] Очередь браков: попарно — дата `MARR`, год первого ребёнка, смерть бездетного супруга раньше детей другого брака, годы рождения супругов, иначе порядок файла. В базе хранится порядок файла. Сверено с заметками у всех двенадцати многобрачных. Явное поле очереди появится с редактором.

## Приложение — этап 1

Сервер на Python, интерфейс на TypeScript. Стенд больше не правится: решения переносятся из `docs/decisions.md` и сверяются с ним по числам.

- [x] Шаг 1. Каркас: сервер отдаёт API и интерфейс, запуск одной командой, git.
- [x] Шаг 2. Разбор GEDCOM без потерь, общая модель, SQLite, загрузка командой.
- [x] Шаг 3. Раскладка отдельным модулем, координаты совпадают со стендом в десяти режимах.
- [x] Шаг 4. Холст: карточки и связи пяти стилей в двух темах, зум, протяжка, линейка, выбор человека. Разметка связей совпадает со стендом побайтно в двадцати режимах.
- [x] Шаг 5. Панель человека, поиск, сворачивание веток, ручной сдвиг среди братьев.
- [x] Загрузка `.ged` через интерфейс и перезалив в существующий род со сводкой изменений.
- [x] Шрифты лежат в проекте (`web/src/fonts`, 20 файлов, 698 КБ): приложение работает без интернета. Пересобрать набор — `web/fetch-fonts.py`. Макеты по-прежнему берут шрифты с Google.
- [ ] Состояния «выжжен», «скрыт», «также в другом роду», метки и портреты рисуются, но в данных их пока нет. Посмотреть можно по адресу с `?demo=marks`.
- [ ] Портреты: хранение снимков в папке на диске, загрузка снимка человеку и выключатель портрета у выбранных людей — сейчас выключатель один на всё дерево. Этап 3, редактор.
- [x] Смена стиля и переворот основателя не сбивают вид: выбранный человек или тот, кто был в центре, остаётся на месте экрана.

## Черновики на подумать

Идеи, которые понравились, но пока не нашли места. Образцы — `mockups/направления/метки-по-стилям.html`.

- **Знаки-сноски в газете.** У каждой метки свой типографский знак — †, ‡, §, ¶ — своим цветом после имени. Знаком метки на карточке не взят: спорит с надстрочной римской цифрой очереди брака. Тема интересная — может пригодиться в другом месте газетного стиля.
- **Ярлыки картотеки в ночном кабинете.** Цветные выступы на верхнем крае карточки рядом с ярлыком рода, как разделители в ящике. Очень понравились, но легко спутать с самим ярлыком рода. Основным знаком метки пока выбраны кнопки.
